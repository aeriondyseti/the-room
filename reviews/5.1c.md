# Review — 5.1c `/restart` in the TUI

- **Trigger:** Kevin needed to restart the room service to load v0.0.19. `room shutdown` from his shell failed
  closed (`identity_unresolved`: human PowerShell chains end at an `explorer.exe` whose launcher has exited). Astra is
  fixing that false negative separately in 2.3b. The TUI had no human restart control.
- **Change:** a `/restart` command. The TUI's connection is the human by construction, so it calls the existing
  human-only `shutdown`:
  - the service finishes in-flight requests and keeps queued deliveries in the ledger, and no agent is interrupted;
  - the TUI's existing reconnect then auto-starts the new service;
  - it takes a second Enter to confirm, and editing the draft cancels a pending confirmation;
  - it's listed in `/help`.
- **Also:** the TUI colour tests pin colour themselves (`src/tui/force-color.ts`), so `npm test` passes in a
  non-TTY shell without `FORCE_COLOR`. Found by Astra.
- **Review:** a small UI change on an existing, qualified service path (graceful shutdown is covered by 4.2),
  cross-reviewed by Astra. Tests: 207/207 without FORCE_COLOR.
