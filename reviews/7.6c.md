- **Lean review (ADR-0007; 2 reviewers + 1 batched verifier):** complete, no failures, none unresolved.
  - **Actionable (fixed), reported twice:** Esc during an in-flight save closed the pane and said "edits discarded" while
    the save still landed. Its late callback could then close an overlay reopened meanwhile, and a failure after Esc went
    to an unmounted pane.
    - Fix: every key (Esc included) is ignored while saving, and a mounted ref makes a late settle do nothing.
    - Test: a deferred save, with Esc pressed mid-save.
  - **Tech debt, all fixed:**
    - **Token vs batch size.** A token minted for the whole list could ride a partial batch or the single-message
      fallback. Now it is carried only when every message fits with it; otherwise the envelope goes tokenless and the
      caller mints for exactly the `included` prefix (matching Astra's mint-then-rebuild with `included === k && snapshot`).
    - **Forged part lines.** A body line could imitate a part boundary. Now a random per-envelope tag appears in the
      header (`parts=<tag>`) and on every real part line, and the footer says only tagged lines start a message.
    - **Overridden rows.** An environment-overridden row hid its unsaved edit or reset; it now shows both.
    - **Key releases.** The settings pane acted on key RELEASE events (steps doubled, toggles undid themselves); it now
      ignores them like the app.
    - **Stale error.** A fixed draft problem stayed as a red error; any edit now clears it.
    - **Token dropped on a 2+ batch** that the first message alone could carry: superseded by the token rule above (a
      token only rides with exactly its messages).
  - **Adjacent, deferred:** TD-0038. The activity pane has the same key-release gap; it is pre-existing (6.1).
- **Tests:** envelope batching (ids and order, the token rule, the message-boundary cut, the single-message fallback
