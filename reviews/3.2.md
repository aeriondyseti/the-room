# Review — 3.2 Composer and commands (plus the real-room TUI)

## Gate (lean profile, ADR-0007)
- **Run:** `wf_7da55d3d-d5f`, base `main` (v0.0.7) → head `a3ff98e`, with 2 reviewers and 1 batch verifier
  (3 agents).
- **complete: true** · 0 failures · **1 actionable** (reported twice) · several tech-debt findings.

## Actionable — fixed
- **Reconnect didn't refresh the delivery states of messages already on screen** (conf 88; invariant 3,
  subscribe contract).
  - A reconnect now re-reads the whole loaded window plus everything new, with deliveries, page by page.
  - If the page cap is hit, it shows a notice instead of stopping silently.
  - Test: a delivery that silently fails during an outage shows as `✗ failed` after reconnect.

## Tech debt worked immediately
- **"Not sent" was shown for sends with an unknown outcome** (conf 78; invariants 2 and 3).
  - "Not sent" is now used only when provable: a validation code, or not connected.
  - Timeouts and drops say "Send outcome unknown — press Enter to resend safely", and the resend reuses
    the same `client_message_id`, so the room deduplicates it.
  - Tests cover both cases.
- **Text typed while a send or command was in flight was erased on completion** (conf 60). The draft now
  clears only if it still equals what was submitted.

## Also fixed during the sprint
- Help overlay rows were being shrunk to zero height by Yoga. Overlays are now top-aligned and set
  `flexShrink={0}`.
- The status bar was clipped when scrolled at narrow widths. The scroll state now owns the line.
- Ink mis-measured the rounded-border composer (right edge short by 9 columns). The composer is now drawn
  frameless, with a rule, the `To:` line and the input rows.

## Deferred
- **TD-0015:** TUI reconnect and history tunables (backoff, failure threshold, history limit, catch-up page
  cap) are literals.
