# Review — 6.8 Layout toggle (top bar ⇄ left panel) + ccstatusline-style usage bars (v0.5.0)

- **Trigger (Kevin, room):**
  - "Can we have a toggle to swap between top-bar and left-bar forms? I'm still not sure which one I like most / which one is easiest to read."
  - "Also consider use of color to make groups more distinct, and adopting the 'progress bar' format that my current ccstatusline config uses."
- **Split:** Astra researched ccstatusline's presentation (read-only: Kevin's settings plus the installed renderer) and wrote the spec. Claude implemented it.
- **Change:**
  - **Switching:** `/layout [top|left]` and Ctrl+B switch the layout. The choice is saved per room in `.room/tui.json` (atomic, serialised; other keys kept), never in harness config.
  - **Starting layout:** set by `room tui --layout` or `ROOM_TUI_LAYOUT`. Invalid values fail loudly.
  - **Narrow terminals:** below `max(tuiPanelBreakpoint, tuiPanelWidth + 51)` columns the TUI shows the top bar with a notice, without overwriting the saved preference.
  - **Left panel:**
    - agents are shown as name, status, a context bar and model · branch;
    - plan usage has one window per row, with the reset on a continuation row;
    - `(stale)` / `(last known)` sit on the account heading;
    - other notes wrap;
    - "you:" sits at the bottom.
  - **Bars:** both layouts use ccstatusline's `slider` (10 cells, ▓/░, one-decimal %).
  - **Colours:** fixed group colours from Kevin's palette (256-colour): 5h 140, weekly and model limits 111, context 178, model and branch 30, dirty count and reset 96.
  - **Status markers:** unknown is `n/a` with no bar; stale is dim and colourless; a high reading (≥ 65%) gets a bold `!` in colour and in NO_COLOR.
  - **Fallbacks:** whole metrics wrap in the top bar and fall back to plain numbers if a bar can't fit.
- **Lean review (Workflow):** complete: true, 2 actionable, both fixed in 35b3763.
  - **Size:** the run used 3 reviewers plus one verifier per finding (15 agents). That is more than ADR-0007's ≤ 3-agent shape; later runs go back to a batched verifier.
  1. On a short panel, usage rows and their qualifiers were silently sliced. Now usage drops bars and reset rows first, then ends with "+ more usage · /layout top". The qualifiers moved onto the account heading, so no shown value loses its label.
  2. A stale token-only context reading (no known limit) lost its "?". Restored.
- **Tech-debt findings fixed as well:**
  - concurrent layout saves shared a tmp path and could persist an older choice or report a false failure; they're now serialised with unique tmp names, and only the latest choice reports a failure;
  - the notice's width is computed by the same rule as the layout (`leftPanelMinCols`);
  - `startingLayout` takes typed inputs.
- **Deferred:** TD-0025 (`mono` is now unused on several render functions).
