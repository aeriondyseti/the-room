# Review — 6.13 Composer keys and a growing composer (v0.7.0)

- **Trigger (Kevin, room):**
  - "ctrl+arrow keys to navigate per word; and expanding the composer so that it supports more than 4 lines without writing into the bottom bar."
  - Kevin also had Astra spec Ctrl+Backspace (delete word) and Ctrl+Enter (newline, replacing Alt+Enter): `docs/COMPOSER-KEYS-SPEC.md` (66f0b46, 4a55ffd, cherry-picked).
  - Kevin's live Windows Terminal key probe (via Astra): Enter CR, Ctrl+Enter LF, Backspace DEL, Ctrl+Backspace BS, Ctrl+Left/Right ESC[1;5D/C.
- **Change:**
  - **Word editing:** grapheme-safe pure helpers (`wordLeft`, `wordRight`, `deleteWordBackward`). Words are whitespace-delimited tokens, as the spec defines.
  - **Keys:**
    - Ctrl+Left/Right move by word; Ctrl+Backspace, Ctrl+W and CSI-u ESC[127;5u delete a word; DEL deletes one character.
    - Ctrl+Enter inserts a newline and never sends, runs or confirms: LF in Windows Terminal, CSI-u ESC[13;5u, or a trailing backslash.
    - Alt+Enter is ignored in Windows Terminal (it's the terminal's fullscreen) and adds a line elsewhere.
    - The composer hint reads per terminal.
  - **Raw key identity:** Ink's `useInput` collapses BS/DEL and hides LF. `useRawKey` keeps the raw bytes of the key being handled, from Ink's own input emitter (no node_modules patch, one input path). BS counts as Ctrl+Backspace only in Windows Terminal (`WT_SESSION`).
  - **Growing composer:** a visual-row model (hard newlines plus soft wraps by display width; wide chars count two, tabs two).
    - It grows up to `ROOM_TUI_COMPOSER_MAX_ROWS` (12), bounded so the conversation keeps 3 rows.
    - It scrolls internally to follow the cursor, with up/down gutter markers.
    - It never draws over the bottom bar.
    - The top-grid height guard now counts the real composer, feedback and suggestion rows (TD-0027 fixed).
  - **Test fix:** `server.test` cleanup retries EBUSY. The detached service now exits right after releasing its lock, and Windows briefly holds the directory.
- **Lean review (3 agents):** complete: true, 2 actionable (each reported twice), fixed:
  1. **Cursor inside a grapheme.** Left/Right/Backspace/Delete stepped by code point, so the cursor could sit inside an accented letter or a ZWJ emoji. `visualRows` then lost it and the window jumped to the top. They now move by grapheme, and `visualRows` places the cursor on the grapheme that contains it.
  2. **Tab width.** Tabs were budgeted as 1 column but drawn up to 8 wide. They're now shown as two spaces, so measured width equals drawn width.
- **Tech-debt findings:**
  - The Ctrl+Enter hint was shown everywhere, though only Windows Terminal is qualified. Fixed: the hint and Alt+Enter behaviour are per terminal.
  - Untested acceptance cases → TD-0029: app-frame tests for the left layout, resize, suggestions with feedback, and a physical-terminal check.
