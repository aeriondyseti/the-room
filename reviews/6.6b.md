# Review — 6.6b Claude usage without extra endpoint calls (v0.3.1)

- **Trigger:** Kevin: "the usage endpoint does have rate-limiting, so we should try to throttle our calls to it"; then
  "piggyback on ccstatusline's values so that the usage endpoint only needs to get called once".
- **Change:**
  - ccstatusline's own cache (`~/.cache/ccstatusline/usage.json`: 5h, weekly and Fable with reset times, plus only a
    token hash) is now the **primary Claude source**. It costs zero endpoint calls, reads no credentials, and takes
    its freshness from the file mtime.
  - The chain is: ccstatusline cache → throttled usage endpoint (opt-in) → statusline tap.
  - The endpoint throttle matches ccstatusline:
    - at most one call per 5 minutes per profile, through a shared cache file that holds numbers only;
    - on a 429, wait for Retry-After (else 5 minutes);
    - errors are reused for 60s.
- **Live:** ccstatusline's cache on Kevin's machine read 5h 7%, weekly 21%, Fable 22%, with resets.
- **Tests:**
  - the mapping, skipping zero placeholders;
  - provider errors;
  - the chain, where only the tap is flagged as a reduced fallback;
  - the throttle: interval, cross-instance sharing, Retry-After back-off and error reuse.

  Tests use memory-only throttling so they never write to the real home folder. The first run did write there; the
  stray files were removed. 272/272.
- **Review:** a small follow-up on 6.6's reviewed code; cross-review requested from Astra.
