# Review — 6.1 Full activity view (v0.2.0)

- **Scope:** shared activity contract (src/contracts/activity.ts, agreed with Astra), a hardened record tail,
  the Claude parser, ActivityReader, ActivityService plus the `activity` IPC request/event, and the TUI
  `/activity @name` pane. Astra's Codex parser is integrated too (their own review: reviews/6.1-codex.md; my
  contract review in the room).
- **Method:** lean local-code-review (ADR-0007), 2 reviewers + 1 batch verifier. complete: true, failures: none.
- **Actionable (2, each reported twice), fixed:**
  1. `activity` requests polled concurrently with the timer pass, so the same bytes were parsed twice under new seqs.
     Polls are now serialized per participant inside ActivityReader (a concurrency test is included).
  2. The pane's coverage/backlog/reason were frozen at open (invariant 3). They now refresh after each event and
     every 3s, and a test covers unavailable → live.
- **Tech debt, all fixed:**
  - a transient locate miss re-read the tail as duplicates: the stream and cursor are now kept, and the cursor is
    only set after stat (test);
  - events during a load triggered repeated reloads: loads are now token-guarded and in-flight events are buffered;
  - the pane list was unbounded: it's capped at 1000 items, with an "earlier activity isn't retained" label;
  - poll interval: a new `activityPollMs` tunable.
- **Live check:** a throwaway fixture's real transcript produced 12 items with full coverage, room tool calls paired
  with their results, and 12 live events (scripts/probes/activity-live.mjs).
- **Isolation:** a no-feedback integration test (a fake HUMAN DIRECTIVE envelope and a room_send call in the transcript
  create no message, delivery or binding change) plus an import-isolation test (delivery, registry, adapters, MCP and
  monitor never import the observer).
- **Re-review:** skipped under the lean budget; the fixes are targeted and each has a test.
