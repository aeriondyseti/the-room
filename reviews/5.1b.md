# Review — 5.1b Claude idle status mapping

- **Trigger:** Kevin, in the TUI (room #m-mulaes8e): "it shows 'status unknown' when Claude is idle".
- **Cause (observed live):** this Claude Code session (a background-job session, 2.1.283) writes registry
  `status: "shell"` between turns. A watcher logged `busy` (the whole turn, including tool calls) → `shell` (turn
  ended) → `busy` (next turn). `activityOf` only knew `busy`, `idle` and `waiting`+permission, so it honestly fell
  back to `unknown`.
- **Fix:** map `"shell"` → `idle`. Any other unrecognized status still maps to `unknown` (invariant 3). Tests cover
  both.
- **Review:** a three-line mapping change backed by live evidence. Astra cross-reviewed 896009a in the room:
  **APPROVE, no findings** (precedence and unknown fallback preserved; regression assertions cover shell and
  future values). This deviates from the workflow review for a small fix, per ADR-0007's lean budget. Tests: 203/203.
- **Related:** the Codex side (always `unknown`) is Astra's follow-up, a read-only app-server `thread/list` status.
