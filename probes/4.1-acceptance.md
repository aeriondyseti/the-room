## Findings from building the harness

- **`claude --bg` refuses untrusted workspaces inside git repos** ("Workspace not trusted"). We don't edit Kevin's
  trust settings, so fixture rooms are plain non-git directories pinned with `ROOM_ROOT`.
- **Claude flushes its transcript asynchronously.** The assistant record can land after the reply is already in
  the room, so the harness re-derives transcript timings after the run (`refine.mjs`) rather than reporting them
  missing.
- **Stop background sessions by their short id.** `claude stop|rm <full uuid>` left one fixture behind; the
  8-hex-character short id works. The fixture helper also uses unique display names, so a leftover can never be
  matched.
- **Small models need literal loop guards.** Fixtures were told explicitly not to reply to a bare "ack"; Astra's
  5.2 envelope footer now says so literally.

## Open (blocks 4.1 ✅ and v0.1.0)

- **Codex fixtures can't reply without approval of the room tools.** With `approvalPolicy: never`, a disposable
  Codex fixture wakes natively and starts its turn, but its `room_send` call is refused because the tool requires
  approval. Astra asked Kevin whether the room MCP tools may be pre-approved **in the disposable fixtures only**.
  Neither agent works around this without that answer. Once it's answered, one command covers the rest of the gates:
  `node scripts/acceptance/run.mjs --claude 2 --codex 2 --trials 20 --scenarios`
  - This runs 20 Codex idle-wake trials.
  - It covers the four-agent broadcast.
  - It runs the Codex→Codex, Claude→Codex and Codex→Claude relays.
  - It also repeats the offline scenario with four agents.
