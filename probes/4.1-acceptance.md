## All timeouts and failures

- **Trials and soak:** none. 140 trial and soak messages across all runs got no `failed` or `uncertain` delivery
  and no missed reply.
- **First four-agent run, Codex→Codex:** the relay ping reached fxd natively; its turn started and it called
  `room_send`. But the ping's body was "relay ping", and the model matched it against the fixture's `RELAY <name>`
  rule, so it relayed back to fxc without a `reply_to`. **Cause: fixture prompt ambiguity.** Fix: the ping body is
  now "ping", and the RELAY rule matches only the uppercase word.
- **First four-agent run, busy Claude:** both messages were delivered, and the second's transcript record carries
  its id. The second landed while the first turn was still running, so Claude attached it to that turn as a queued
  message instead of starting a new turn, and the fixture's "reply exactly once" rule made it answer only the first.
  **Cause: fixture prompt.** Fix: fixtures answer every message they see, including ones attached mid-turn. The room
  behaved correctly: one delivery each, submitted in order.
- Delivery itself never failed: every relevant delivery reached `submitted` on its first attempt.

## Findings from building the harness

- **`claude --bg` refuses untrusted workspaces inside git repos** ("Workspace not trusted"). We don't edit Kevin's
  trust settings, so fixture rooms are plain non-git directories pinned with `ROOM_ROOT`.
- **Claude flushes its transcript asynchronously.** The harness re-derives transcript timings after the run
  (`refine.mjs`) rather than reporting them missing.
- **Stop background sessions by their short id** (8 hex characters). The full uuid left one fixture behind.
- **A Claude message that arrives mid-turn joins the running turn** (a queued-command attachment). Agents must
  treat each room message as its own item, and the 5.2 envelope and skill should keep saying so.
- **Small models need literal wording:** they need explicit loop guards ("don't reply to a bare ack"), and command
  words must not collide with message payloads.
- **Codex fixtures need their room tools pre-approved** to reply unattended. `approvalPolicy: never` alone refuses
  the tool rather than prompting. Resolved with Kevin's fixture-only approval (see above).
