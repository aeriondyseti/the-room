# 5.1 TUI polish: UX pass (before and after)

Date: 2026-09-28 · base v0.0.16 · reproduce any frame with
`npm run build && node scripts/preview-tui.mjs [WxH] [--mono] [--empty|--quiet] [--keys "…"]`, or live with
`roundtable tui --demo [--no-color]`.

Most of the TUI was already in good shape before this pass:
- a clear header, and a two-row participant card per agent (liveness, activity, context);
- per-recipient delivery marks and a composer that shows its addressee;
- a narrow single-column layout;
- help, who and detail overlays.

This pass fills the gaps listed in the 5.1 scope.

## 1. Theming: colour and no-colour

**Before:** colour-only. `NO_COLOR` was ignored because Ink's chalk doesn't read it, and the only way to get plain
output (chalk level 0) would also strip inverse, which hides the composer cursor.

**After:** a `Theme` (`src/tui/theme.ts`) routes every colour through `theme.color()`.
- Monochrome turns on with `NO_COLOR=1` (any non-empty value, per no-color.org), `roundtable tui --no-color`, or
  `TERM=dumb`.
- It drops **colours only**. Bold, dim and inverse stay, so the cursor, emphasis and hierarchy survive.
- Every state that colour alone used to carry now also has a glyph or a word.
  - Delivery marks were already glyph + word (✓ replied, ? uncertain, ⋯ offline, …).
  - Liveness dots were already distinct (● ○ ◌ ⚠).
  - **High context usage gains a `!`** in monochrome (`ctx 88%!`), since red and yellow can't show.

```
● claude_build… ctx 88%! │   ┌ ts          ← monochrome: no colour codes, bold/dim/inverse kept
  needs approval         │   │ await source.request('send', …
○ codex_review… ctx 12%? │   │ await source.request('pause', …
```

Tested: a monochrome render contains no colour SGR codes at all, still contains inverse (the cursor), and shows
`ctx 88%!` and the glyph+word delivery states. The colour render is unchanged.

## 2. Message formatting: code blocks

**Before:** code in a message was word-wrapped like prose, which re-flowed it and dropped its indentation (for
example `    return  y;` collapsed its spaces):

```
│ 04:02 claude → astra  ↩ #2  #3
│   Yes — composer is mine. I will send you the IPC calls it needs:
│
│   send, pause, resume, retry
```

**After:** fenced blocks (```` ``` ```` or `~~~`, with an optional language) render behind a gutter.
Indentation is kept exactly, and long lines hard-wrap instead of re-flowing, so the code stays readable and
copyable at any width. An unclosed fence runs to the end of the message, and code is sanitized like everything
else (invariant 9).

```
│ 04:02 claude → astra  ↩ #2  #3
│   Yes — composer is mine. These are the IPC calls it needs:
│
│   ┌ ts
│   │ await source.request('send', { to, body, clientMessageId });
│   │ await source.request('pause', { stopRequestBody: null });
│   └
│
│   I will ping you when it is ready for a look.
```

## 3. Empty and first-run states, with onboarding hints

**Before:** one generic "The room is quiet" block, whether or not anyone had joined.

**After:** two distinct states.
- **First run (no agents):** a welcome with three numbered steps:
  1. how agents join ("join the room as <name>" → `roundtable_join`, or `roundtable join --as`);
  2. what happens next;
  3. where to look when something's off (`roundtable doctor`, docs/ONBOARDING.md, `?`).
- **Agents but no messages:** says who is here and suggests `@<first name>` to address one.

```
 vibe-pairing                                                                 0 agents  ● connected
PARTICIPANTS             │ Welcome to the room — no agents have joined yet.
none yet                 │
                         │ 1. In each agent's session, ask it to join: "join the room as <name>".
you: Kevin               │    It uses the roundtable_join tool (or `roundtable join --as <name>` from its
                         │    shell).
                         │ 2. Joined agents appear here with their status. Enter sends to
                         │    everyone; start with @name to pick one.
                         │ 3. Something off? Run `roundtable doctor`, or see docs/ONBOARDING.md. …
```

## 4. Help overlay and key hints

Hints were already present (composer: Enter / Alt+Enter / Tab / ?; status bar: scroll / help / quit). The help
overlay now also documents monochrome mode (`NO_COLOR=1` or `--no-color`), and `roundtable tui --help` lists
`--no-color`.

## 5. Delivery detail: runtime context

`/detail` now shows which native runtime handled each attempt, when the service recorded one. For Codex that is
the executable and CODEX_HOME, which is what you need to reconcile an `uncertain` attempt by hand:

```
? astra uncertain
    → codex astra-session
    attempt 1 · 04:03 uncertain
      via C:\Users\you\.codex\bin\codex.exe · home C:\Users\you\.codex
      codex queue timed out after the message was handed over
      → It may already have arrived; check before retrying.
```

## 6. Tunables (TD-0013, TD-0015)

The layout and reconnect literals are now config (`ROUNDTABLE_TUI_*`):

| Tunable | Default |
|---|---|
| panel width | 26 |
| panel breakpoint | 90 cols |
| history limit | 500 |
| catch-up page cap | 50 |
| reconnect backoff | 250ms → 5s, doubling |
| failures before "disconnected" | 3 |

`roundtable tui` passes them through, and tests cover the defaults, the overrides and the layout effect.

## Regressions

None found. The full suite passes: 195 tests, including every earlier TUI test (layout, scroll, composer, overlays,
reconnect, the real-room integration) plus the 5.1 tests in `src/tui/polish.test.tsx` and `src/core/config.test.ts`.
